## 6주차수업내용
실습1: 자바스크립트 활용하기 -  JS 폴더를 생성하고 파일 복사한다. js에 다운받은 부트5(.js) 라이브러리를 복사하여 내부 로컬에서 연동한다. Html 파일 내에서 직접 js삽입(head)한다.
    <script>
    window.onload = function() {
    alert("메인 페이지 로딩 완료");
    }
    </script>
    를 넣어 페이지 새로고치면 "메인 페이지 로딩 완료"라는 팝업 창이 뜨게 된다. 왜냐하면 window.onload가 윈도우를 열(로드)때마다 뜨게 하는 것이기 때문이다.

실습2:  자바스크립트 활용하기 - "무료 플레이를 클릭하면 즐거운 플레이 되세요"라는 화면이 작게 뜨게 된다. 아까와 다른 이유는 이번 코드는 버튼을 클릭하였을때 뜨기로 되어 있기 때문이다. 그래서 새로고침을 한다고 했을때 뜨지 않고 무료 플레이 버튼을 눌러야 뜨는 것이다.

실습3: 자바스크립트 기본 문법1 - 블록 스코프 내에서만 접근이 가능한 if문이다. 첫번째 줄은 접근 가능하고 두번째 줄은 접근이 불가능하다. 세번째 줄은 에러가 나지 않는데 두번째 줄을 주석처리하고 페이지를 다시 로딩한다면 세번째줄도 에러가 나는 것을 볼 수 있다. 이렇게 두번째 줄을 주석을 해야 세번째줄이 에러가 나는 이유는 인터프리터 언어는 한줄씩 실행이 되기 때문이다. 즉, 두번째 줄에서 에러가 났기 때문에 멈춰서 세번째 줄은 실행되지 않은 것이다.

실습4: 자바스크립트 기본 문법2 - var은 고전적인 방식이다. 코드를 봤는데 똑같은 변수를 선언하고 값을 변경했는데 가능한 방법이다. let과 const는 되지 않는다. 호이스팅이라고 하는 것은 코드 실행전, 선언부를 해당 스코프 상단으로 끌어올린다.

실습5: LOL 기능 구현 중 실시간 챔피언 검색하기 - 검색창을 만들어뒀지만 아무런 반응이 없기 때문에 기능을 추가해야한다. 텍스트창 같은 것이 있는 것을 form창이라고 부른다. 이를 자바스크립트를 이용해 버튼을 누르면 실행이 되도록 본다. search를 searchForm으로 바꿔주고 id가 고유값이다. 그리고 search.js 파일을 만들어서 html 최하단에 연동한다. 그러고 페이지에서 검색을 해보면 오류가 난다. 다시 indev=x.html.dp 하단으로 가서  <script src="js/search.js"></script>를 해주면 오류가 나지 않는다. 내가 클릭을 하는 순간 타입 중 submit이 실행이 되는 것이다.


<소감 및 문제해결>: 우리가 사용하는 웹사이트에서 팝업이 뜨는 경우를 자주 보았는데 그 팝업창을 구현해보니 신기했다. 그리고 자바스크립트의 문법이 복잡하고 시대에 따라 많은 변화가 있는 것을 알게 되었다. 그리고 우리가 구현한 것(보통 .js파일)을 제대로 불러오기 위해 index.html에 연결을 해줘야할 것을 주의하게 되었다.

## 7주차수업내용
실습1: 실시간 챔피언 검색하기1 - Js 파일인 search.js 파일을 작성하고 html 최하단에 연동한다. DOM(Document Object Model)이라는 것을 추가하였는데 이것이 필요한 이유는 HTML 로딩을 위한 표준 구조와 트리 구조(DOM)로 변환하여 관리하는 역할을 하기 때문이다. 이것은 새로운 창을 열면서 검색 결과 출력한다. 입력: 이벤트, 검색 : 이벤트이고 F12 개발자 모드로 소스를 확인할 수 있다.

실습2: 실시간 챔피언 검색하기2 - 해당 코드를 뉴스 섹션 하단에 붙여넣기를 해준다. 하지만 아직 동작하지 않는 것을 볼 수 있다. 왜냐하면 검색을 해야 보여지게 되어있기 때문이다.
구현시키기 위해  search.js에 기존에 있던 코드는 주석처리 해주고 새로운 코드를 넣어준다. 문자열 앞에 이름이 들어가 있는 것을 볼 수 있는데 이것은 객체배열로 키와 값으로 되어 있어서 키로 검색읋 하면 빠르게 찾을 수 있다.

실습3: 아트록스 검색하면 아래에 있는 화면이 출력되는 것을 볼 수 있다. 기본 동작(코드)를 이해해 보자면, 현재 폼의 id는 searchForm(동일)이고 핵심 함수는 performSearch이다. 데이터 셋으로 부터 filter 조건 충족하고 키워드 가운데 출력해주는 것은 searchKeywordDisplay이다. 필터 결과 카운팅(숫자)는 0개인 경우 화면을 처리한다. 탭(기본) 전환은 switchCategory이고 카테고리 클릭(빨간 왼쪽 테두리)은 Type으로 판단한다.


<과제1> - 데이터정의 추가하기: 저번 과제에서 추가한 멜, 유나라, 자헨 카드에 이름, 역할, 난이도를 표시하고, 상세 보기 버튼을 누르면 Bootstrap 모달창을 통해 챔피언 상세 정보가 보이도록 구현하였다. 또한 search.js의 CHAMPIONS 배열에 신규 챔피언 데이터를 추가하여 검색창에 한글 이름 또는 영어 이름을 입력하면 해당 챔피언이 검색 결과 화면에 뜨도록 구현하였다. 

<과제2> - 검색어기능 추가하기: 검색 결과 화면이 표시된 상태에서 검색창을 공백으로 두고 Search 버튼을 클릭하면 showMainScreen() 함수가 실행되도록 구현하였다. 이 함수는 검색 결과 영역을 숨기고, 기존 메인 화면의 section들을 다시 표시한다. 빈 검색어 입력 시 검색 결과 화면에서 메인 화면으로 정상적으로 되돌아간다. 즉, 검색어가 없거나 공백인 경우에는 showMainScreen() 함수가 실행되어 검색 결과 화면을 숨기고 기존 메인 화면으로 돌아간다.


<소감 및 문제해결>: 수업 시간에 아트록스의 이름을 검색해도 화면이 넘어가지 않아서 오류를 해결하느라 애먹었다. 그래도 수업이 다 끝난 후에 혼자 천천히 코드를 살펴보니 내가 상단과 하단에 같은 코드를 입력하여 꼬인 것을 알게 되고 화면이 정상적으로 뜰 수 있게 되었다. 이렇게 스스로 오류를 수정하며 해결해보니 실력이 조금이라도 성장한 기분이 들었다.

실습3: 데이터베이스 연동 (프로젝트 dev 보드를 통한 확인) - Quarkus의 Dev UI를 통해 데이터베이스 연동 상태를 확인하였다. 서버 실행 후 http://localhost:8080/q/dev/에 접속하여 DB connection pool과 MySQL 연결 정보를 확인하였고, champion 테이블이 생성되었는지 확인한 후 http://localhost:8080/champions 경로에서 챔피언 데이터가 JSON 형식으로 출력되는 것을 확인하여 데이터베이스와 웹 서버가 정상적으로 연동된 것을 아래 화면처럼 확인할 수 있었다.

<과제1> - 챔피온 검색 결과 모달창 띄우기: 검색 결과 화면에서도 챔피언 상세 정보를 확인할 수 있도록 하기 위해 search.js의 CHAMPIONS 배열에 modalId 속성을 추가하였다. modalId에는 index.html에 작성된 각 챔피언 모달의 id 값을 저장하여, 검색 결과 카드와 기존 모달창이 연결되도록 하였고 검색 결과 카드 HTML에 상세 보기 버튼을 추가하고, Bootstrap의 data-bs-toggle="modal"과 data-bs-target 속성을 사용하였다. data-bs-target 값에는 각 챔피언 데이터의 modalId를 적용하여, 검색된 챔피언에 맞는 상세 모달창이 열리도록 구현하였다. 결과적으로 사용자가 검색창에 챔피언 이름을 입력하면 검색 결과가 출력되고, 검색 결과의 상세 보기 버튼을 클릭하면 메인 화면의 챔피언 카드와 동일한 방식으로 상세 정보 모달창을 확인할 수 있다.

<과제2> - 모든 페이지에 동일 적용하기: 다크/라이트 모드 전환 기능의 JavaScript 호출 방식을 기존에는 HTML 버튼 내부에서 onclick="toggleTheme()" 방식으로 함수를 직접 호출했지만 이를 제거하고 이벤트 리스너 방식으로 변경하였다. toggleTheme() 함수는 body에 light-mode 클래스를 추가하거나 제거하여 테마를 변경하는 역할을 한다. theme-toggle-btn 클래스를 추가하고 toggle.js에서 addEventListener("click", toggleTheme)를 사용하여 버튼을 클릭하면 toggleTheme() 함수가 실행되도록 구현하였다. toggleTheme() 함수는 body에 light-mode 클래스를 추가하거나 제거하여 화면의 다크/라이트 모드가 전환되도록 하였다. 마지막으로 메인 페이지처럼 다운로드 페이지도 동일한 토글 버튼과 toggle.js 파일을 적용하여 두 페이지 모두에서 다크/라이트 모드 전환이 가능하도록 구현하였다.

## 11주차수업내용
실습1:  세션 활성화 설정 추가와 DB 사용자 체크(login_check) 완성하기 - 로그인 후 사용자 상태를 유지하기 위한 세션 기능을 구현해본다. SessionConfig.java라는 파일을 새로 생성하여 세션 저장소와 세션 핸들러를 등록하고 세션 유지 시간 및 HttpOnly 쿠키 옵션을 설정하였다. 그리고 AuthResource.java에서 로그인 성공 시 사용자 정보를 세션에 저장하고 로그인 후 페이지 접근 시 세션 존재 여부를 확인하여 비로그인 사용자의 접근을 차단하도록 구현하였다. 
그래서 적어놓은 사용자 정보인 아이디: guest 비밀번호: 123123이 아니라면 로그인이 되지 않는다. 그리고 로그인 이후 개발자모드를 켜서 Application에 Cookies에 들어가 확인해 구현된 것을 볼 수 있다.

실습2: /logout 로그아웃 엔드포인트 구현하기 - 로그인 이후에 로그아웃을 누르게 되면 제대로 로그아웃이 되는 로그아웃 기능을 구현해본다. 로그아웃 요청 시 현재 세션의 ID와 로그인 사용자 정보를 콘솔에 출력한 뒤, context.session().destroy();를 사용하여 세션 데이터를 삭제된다. 이후 메인 페이지로 이동하게 설정하고, /after_login 재접근 시 로그인 페이지로 차단되는지 확인하여 로그아웃 동작을 검증할 수 있다.

실습3: 회원가입 화면 구현하기 - 회원가입 화면을 구현하고 로그인 페이지와 연결시켰다. login.html의 로그인 버튼 아래에 회원가입 버튼을 추가하여 /register 페이지로 이동하도록 하였고, AuthResource.java에 /register 엔드포인트를 작성하여 register.html이 출력되도록 하였다.
register.html은 기존 index.html의 네비게이션 바와 main.css를 재활용하여 전체 페이지 디자인을 통일하였다. 회원가입 폼에는 아이디, 패스워드, 패스워드 확인, 이메일, 연락처 입력칸을 구성했다. dev UI에도 구현된 것을 볼 수 있다.

실습4: 입력 값 유효성 검사 추가하기 - js 폴더에 input_check.js 파일을 생성하고 validateAndShowModal() 함수를 작성한다. 아이디는 4~20자 영문/숫자만 허용하고, 패스워드는 8자 이상이며 영문, 숫자, 특수문자를 포함하도록 정규식을 사용해 검사한다. 또 패스워드 확인 값이 일치하는지 확인하고, 이메일과 연락처 형식도 검사하도록 구현하였다.
입력값이 조건에 맞지 않으면 Bootstrap의 is-invalid 클래스와 invalid-feedback 영역을 사용하여 오류 메시지 아래와 같은 사진처럼 화면에 표시되도록 하였다. 즉 모든 입력값이 유효한 경우에만 registerForm이 서버로 전송된다.

실습5: 암호화 추가하기 - 회원가입 기능에 패스워드 암호화 처리를 추가한다. js 폴더에 input_sha256.js 파일을 만든다. SHA-256 해시함수를 적었는데 이 함수는 브라우저 내장 Web Crypto API의 crypto.subtle.digest()를 사용하여 사용자가 입력한 패스워드를 SHA-256 해시값으로 변환하는 역할을 한다.
register.html에는 해시된 패스워드를 서버로 전송하기 위한 hidden input을 추가한다. 사용자가 입력한 원본 패스워드는 직접 전송하지 않고, hashPassword() 함수로 생성한 해시값을 hidden input인 hashedPassword에 저장한 뒤 name="password" 값으로 서버에 전달되도록 한다.
입력값 검사를 모두 통과하면 가입 확인 모달창이 출력된다. 모달에는 아이디, 이메일, 연락처만 표시하고 패스워드는 ******** (암호화 전송)으로 표시된다. 
이후 사용자가 가입하기 버튼을 클릭하면 submitRegister() 함수가 실행되어 /register_check로 회원가입 데이터가 전송된다.
dev UI에도 구현된 것 아래 사진처럼 볼 수 있다. 회원가입이 정상적으로 처리된 후 새로운 사용자 정보가 DB에 저장되었으며, password 컬럼에는 원본 패스워드가 아닌 SHA-256 해시값이 저장된 것을 확인할 수 있다. 이를 통해 패스워드가 평문으로 저장되지 않고 암호화된 값으로 관리되는 것을 확인할 수 있었다.

<과제> - 로그인 화면 입력값 체크: 로그인 화면에도 회원가입 화면과 동일하게 입력값 유효성 검사 기능을 추가하는 과제이다. js 폴더에 login.js 파일을 생성하고, validateAndLogin() 함수를 작성한다. 
로그인 버튼을 누르면 아이디와 패스워드 입력값을 먼저 검사하도록 하고 회원가입과 동일하게 아이디는 4~20자 영문/숫자만 허용하고 패스워드는 8자 이상이며 영문, 숫자, 특수문자를 포함하도록 구현하였다. 입력값이 조건에 맞지 않으면 is-invalid 클래스와 invalid-feedback 영역을 이용하여 오류 메시지가 표시되도록 하였다. 두 입력값이 모두 유효한 경우에만 loginForm이 /login_check 경로로 전송된다.

<소감 및 문제해결>: 이번 실습에서는 로그인, 회원가입, 입력값 검사, 패스워드 암호화, 가입 완료 페이지까지 구현하면서 웹 페이지의 화면 구성과 서버 연결 흐름을 이해할 수 있었다. 처음에는 로그인 페이지와 회원가입 페이지의 코드가 섞이거나, 버튼을 눌러도 원하는 페이지로 이동하지 않는 문제가 있었다. 또한 회원가입 화면에서 유효성 검사 메시지가 보이지 않거나, 기본 confirm 창이 뜨는 등 과제에서 요구한 Bootstrap 모달창과 다른 결과가 나타나기도 했다.
이번 실습을 통해 오류가 발생했을때 HTML의 id와 name 속성, JavaScript 함수 연결, script 파일 경로, Java 엔드포인트, 데이터베이스 저장 상태까지 차례대로 확인해야 한다는 것을 알게되었다. 그리고 회원가입 기능은 입력값 검사, 모달 출력, 암호화 처리, 서버 전송, DB 저장이 모두 연결되어야 정상적으로 동작할 수 있다는 것을 이해할 수 있었다.

문제해결1 - 처음에는 회원가입 화면에서 입력값 검사는 작동했지만, 패스워드 확인 입력칸 아래에만 빨간 오류 문구가 제대로 표시되지 않는 문제가 있었다. 원인을 확인해보니 JavaScript에서는 passwordConfirmMsg라는 id를 찾고 있었는데, HTML에서는 오류 메시지 div의 id가 다르게 작성되어 있었다. 이를 해결하기 위해 패스워드 입력칸 아래에는 passwordMsg를 추가하고 패스워드 확인 입력칸 아래에는 passwordConfirmMsg를 추가하여 JavaScript와 HTML의 id 값을 일치시켰다. 이 해결과정 통해 입력값 검사 기능에서는 input의 id와 오류 메시지 div의 id가 정확히 연결되어야 한다는 것을 알게 되었다.
처음 사진이 전이고 두번째가 고친 후 사진이다.

문제해결2 - 회원가입 테스트를 여러 번 진행하면서 같은 아이디가 이미 가입되어 다시 회원가입이 되지 않는 문제도 발생하였다. 이를 해결하기 위해 아래 사진에서 볼 수 있듯이 MySQL에서 lol 데이터베이스를 선택한 뒤 users 테이블을 조회하고, DELETE FROM users WHERE username = 'gsy593'; 명령어를 사용하여 테스트 계정을 삭제하였다. 삭제 후 다시 같은 아이디로 회원가입을 시도할 수 있었다. 이를 고쳐나가면서 데이터베이스에 회원 정보가 저장되는 흐름도 직접 확인할 수 있었다.
